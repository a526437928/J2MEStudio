# 第三、四阶段：显示、按键、诊断与独立游戏模式

版本 0.4.0 (4)，最低 iOS 18.0。通用模式继续使用 `org.j2mestudio.emulator`，独立诊断模式使用 `org.j2mestudio.diagnostics`。二者调用同一套 `GameViewController`、原生桥接、C miniJVM 和 Java API。没有加入商业游戏。

## 实际功能

- 支持自动旋转、锁定横屏或竖屏。画面以游戏原始宽高比显示，控制区域遵守安全区域。
- 支持保持比例适应、整数倍物理像素和原始像素。原始像素指一个游戏像素对应一个屏幕物理像素；若游戏大于可用区域，等比例缩小以完整显示。
- 游戏内“设置 → 显示与按键”可更改方向、缩放、按键整体大小及透明度。可拖动方向盘、键盘和软键；也可逐个拖动、双指缩放数字键。横竖屏布局分别保存，编辑期间暂停游戏输入。数字键重叠或超出区域时拒绝保存并提示。
- 每个游戏的配置位于 `Documents/Configurations/<UUID>.json`，与 RMS 分开；可以导出配置。配置随卸载而删除，更新前仍须备份完整 Documents。
- 运行前自动备份当前游戏 RMS，保留最近三份，也可在游戏列表菜单手动备份或恢复最近备份。恢复前先备份当前数据，保留回退路径；只操作本游戏 UUID。
- 每次运行记录 `last-session.json` 和 `last-run.log`；下次运行先归档历史，避免覆盖异常前日志。保留 miniJVM 原有信号处理，捕获标准输出与错误输出，菜单支持导出日志及环境信息。
- 日志捕获不等同于完整 iOS 原生崩溃堆栈。SIGKILL、系统内存终止等情况不保证留下最后一行；必要时从 iPhone 分析数据取得系统 `.ips`。

## 独立 App

`scripts/prepare_standalone.py` 验证 JAR 并生成新的隔离源码目录，包含 `embedded.jar`、`standalone.json`、专用图标和构建身份元数据。默认诊断图标由本项目代码生成；可传入有权使用的 1024×1024 PNG。原工程和游戏库不被改写。

App 启动时检测合法内置配置，直接进入指定游戏；无需进入游戏列表或手动导入。退出后可再次启动。屏幕参数、按键默认值可由 JSON 配置，首次保存后尊重用户对该 App 的调整。独立 Bundle ID 对应独立沙盒及游戏存档。

先用 JDK 编译合法诊断 JAR，然后在 Windows 生成独立源码：

```powershell
python scripts/build_java.py all
python scripts/prepare_standalone.py --jar J2MEEmulator/Resources/apps/studio_diagnostics.jar --output build/StandaloneSource --name "Studio 诊断独立版" --bundle-id org.j2mestudio.diagnostics --profile standalone.example.json --confirm-rights
```

在 macOS Runner 编译生成目录：

```bash
BUNDLE_ID=org.j2mestudio.diagnostics DISPLAY_NAME="Studio 诊断独立版" bash build/StandaloneSource/scripts/build_ios.sh
```

必须设置相应 `BUNDLE_ID` 和 `DISPLAY_NAME` 环境变量；`standalone-build.json` 保存身份供检查，不能单凭生成此文件就视为已编译。常规 Actions 已自动执行上述独立诊断构建与运行测试，分别上传两个 App 的 IPA 和 `.app` ZIP。

`--confirm-rights` 是打包者对资源权限的明确声明，不是脚本自动认定商业资源授权。当前唯一实际打包对象是本项目 Apache-2.0 的中文诊断 MIDlet。《诛仙伏魔录》尚未取得合法 JAR，未打包、未验证兼容性。

## 自动化验证范围

- Python：IPA 结构与架构检查、独立源码生成、资源与身份分离、拒绝覆盖、拒绝错误 Bundle ID 和未确认资源权限。
- Swift：原 26 项游戏库/ZIP 检查；另用多种画布、屏幕区域及 1/2/3 倍屏幕密度，验证缩放比例、整数倍及区域约束；验证按游戏配置持久化、RMS 备份轮换、恢复及跨游戏隔离。
- Java：编译真实 API 与自编 MIDlet；宿主进程测试中文 RMS、跨进程持久化与生命周期。宿主通过不代替 miniJVM 运行。
- 通用 iOS App：实际安装在 iOS 26.2 / iPhone 17 Pro 模拟器，经 C miniJVM 执行八个场景：横屏适应、竖屏整数倍、横屏原始像素、另一游戏首次运行、原生信号异常退出、原游戏恢复、另一游戏二次运行、RMS 回退。
- 异常场景在实际 JVM 已写入 RMS 后触发 SIGABRT，保留原核心处理器，检查信号日志及另一游戏 RMS 文件哈希。下一次启动检查存档仍可读取；不把该场景说成游戏进程隔离或所有崩溃都可恢复。
- 独立 iOS App：实际安装不同 Bundle ID，检查直接启动模式、只有内置游戏、两次 RMS 计数，以及竖屏整数倍和横屏原始像素。
- 输入测试经生产按键控制器合成，覆盖按下、松开、长按、组合输入和后台生命周期事件；真实多指触摸、物理旋转与音频必须另在 iPhone 验收。
