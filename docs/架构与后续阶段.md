# 共享核心与当前边界

保留原单一 iOS target、原生桥接和原版 C miniJVM。通用 App 与独立 App 在不同隔离源码目录编译同一 target；不复制或重写第二份运行核心。

```text
SceneDelegate
  ├─ 无 standalone.json → 中文游戏库 → GameLibrary 导入 / 配置
  └─ 有 standalone.json → StandaloneLauncher → 导入唯一内置 JAR
                                            ↓
                             同一 GameViewController
                             显示 / 按键 / RMS 快照 / 日志
                                            ↓
                             jvm_bridge → C miniJVM → Java API / MIDlet
```

游戏库使用稳定 UUID，JAR、配置、存档和备份通过 UUID 关联。同名文件不覆盖，内容相同重复导入复用记录。独立 App 除 UUID 隔离外还有不同 Bundle ID 的系统沙盒隔离。备份完整 Documents 才能保留这些关联。

第二阶段已完成中文游戏库、搜索、封面读取、文件导入和存档隔离，以及真实 miniJVM 诊断 MIDlet 运行。第三阶段已实现显示模式、安全区域、横竖屏按键编辑、RMS 回退与日志导出。第四阶段已实现独立直接启动、图标和身份配置及自动化构建；各阶段的实际构建和测试状态以对应验收报告为准。

独立构建通过 `prepare_standalone.py` 生成新的源码目录和资源，再使用 `BUNDLE_ID` / `DISPLAY_NAME` 构建覆盖参数。专属配置载入 `StandaloneProfile` 和共用 `PlayPreferences`，与通用 App 使用同一套输入和显示逻辑。没有另建可能逐渐偏离的 Java 核心副本。

所有已运行的自动化 MIDlet 均为合法测试资源。用户已在实体 iPhone 反馈诊断程序按键、组合操作和正常退出重开的 RMS 加一通过，尚未逐款验证厂商扩展、3D 与音频输出。用户后来提供了本地《诛仙伏魔录》JAR，已完成只读结构检查；运行与资源分发许可仍待确认，未收入工程、未独立打包，详见游戏兼容记录。

后续需要：依据 iPhone 的实际运行结果修复具体问题，增加合法游戏兼容矩阵和音频/3D 验证资源；核实原 Java 启动类库的对应源码与许可，再评估更广泛分发。不要以宿主 Java 或模拟器测试代替实体 iPhone 验收。
