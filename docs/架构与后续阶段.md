# 复用核心与后续阶段

本阶段保留单一 iOS target、原生桥接和原版 JVM，不复制两份运行核心。

第二阶段：建立稳定唯一的游戏记录 ID、受控导入及独立存档路径；保留原版分辨率/FPS/3D 配置；以原仓库测试 MIDlet 验证首次启动、二次启动 RMS 计数、Canvas、输入、声音与退出。Windows 上只完成 Java 编译，运行验收必须在 iOS 构建成功后进行。测试资源不得替换为未经许可的商业游戏。

第三阶段：完整简体中文、搜索与封面、自定义按键、方向切换、安全区域、保持比例和整数倍缩放、崩溃记录及兼容修复。需要原始键位的按下/释放配对与多键测试，不能只测试按钮点击。

第四阶段：增加一个共享启动配置模型，由 App 启动入口决定游戏库模式或指定合法 JAR 的直接启动模式。独立 target/xcconfig 指定 Bundle ID、图标、名称和专属键位；仍调用同一 `GameViewController` / `jvm_bridge` / miniJVM / Java API。存档以稳定 ID 区分，并因 iOS 应用沙盒自然隔离。为每款游戏单独生成构建产物及兼容性记录。

当前只预留此架构边界，没有实现或宣称已完成独立游戏打包。《诛仙伏魔录》尚无已授权并验证的 JAR，未下载、未打包、未宣称可运行。
