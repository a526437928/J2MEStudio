# 第二阶段：游戏库与可运行诊断 MIDlet

本阶段在原核心上开发。C miniJVM 解释器、M3G、MascotCapsule、音频与原 Java API 均保留。新增内容不等于支持所有 JAR。

## 已实现

- 游戏库 `library.json` 持久化 UUID，游戏保存在 `games/<UUID>.jar`，存档在 `Saves/<UUID>/rms`，分辨率/FPS/3D 配置按 UUID 区分。
- 文件 App 导入、多选、打开方式导入；验证 manifest、入口类与 class 魔数；同名不同内容分别保存，同内容重复导入复用记录，文件丢失后重新导入可恢复原 ID。没有游戏数量上限。
- 中文游戏库、搜索、删除、清除存档、配置菜单、软键及错误提示，保留封面和元数据读取。
- 异步导入、SHA-256 计算及扫描；复制成功且索引原子写入成功后才接受新游戏。失败不会先删除旧 JAR。
- 旧版 JAR 从 `games` 和 Documents 根目录自动接纳。原 JAR 转入 `Import Backups`；旧 `Games Data` 保留原件。只对归属唯一的旧存档复制迁移，对中文文件名碰撞等歧义明确提示，不猜测归属。
- 长按每个键独立计时；同一键有多个来源时引用计数，松开一个来源不释放另一个来源；失去前台和退出时释放按键。
- 平台失活/恢复发送生命周期事件，在现有 Display 事件循环中调用 `pauseApp` / `startApp`；不声称强制冻结了游戏自行创建的全部 Java 线程。
- 防止视图再次出现时重复启动 JVM；初始化和原生退出失败有 UI 提示。`last-session.json` 和 `Sessions` 保留运行状态与历史。未完成状态可辅助排查，但不是原生崩溃堆栈。
- 自编、Apache-2.0 的 `studio_diagnostics.jar`，包含中文 Canvas、数字/方向键计数、组合键、长按、RMS 中文内容和启动次数。点击游戏库左上角“测试 MIDlet”安装，无商业游戏资源。
- ZIP 元数据解析增加短文件、中央目录结束与空条目检查，用内存映射读 JAR；对单个解压条目限制内存占用，不限制游戏数量。

## 自动化验证设计

`scripts/test_swift.sh` 在真实 macOS Swift 编译器上执行库/ZIP 回归：同名不覆盖、重复导入、持久 ID、重新导入恢复、删除/清除隔离、101 个游戏、大小写扩展名、旧存档明确与歧义迁移、索引写入失败回滚、损坏索引保留原件及非法 ZIP。

`scripts/test_rms_host.py` 使用宿主 JDK 验证 Java RMS 跨进程保存、中文数据、两个根目录隔离及 MIDlet 暂停/恢复标记。这一层不能证明 miniJVM 运行。

`scripts/test_simulator.py` 在 iOS 26.2 / iPhone 17 模拟器安装实际编译的 App，按正常导入路径安装诊断 MIDlet，然后经真实 C miniJVM 运行两次。自动检查 Java 写出的诊断结果、原生会话正常结束及 RMS 启动次数 1 → 2；保存截图和控制台日志。输入由生产按键控制器合成，覆盖重复、按下/释放与组合输入传递，不冒充物理触控测试。

## 当前状态

Windows 已通过 Java 编译、宿主 RMS、Python 打包回归和脚本语法检查。云端执行记录与实际结果在本文件完成云端验收后补充，失败会保留日志，不把编译成功当作模拟器运行成功。

## iPhone 手动验收

1. 用相同 Apple ID、相同最终 Bundle ID 覆盖安装，先备份完整 Documents。
2. 安装“测试 MIDlet”，启动后确认中文画面无方框、无乱码；人工按方向、数字、软键，同时按两个键并长按，确认计数与松开状态。
3. 退出重开，RMS 启动次数加一；切换后台和前台，确认游戏可恢复。
4. 导入同名不同内容 JAR，确认列表保留两项；分别操作后确认存档路径和配置不同。
5. 删除或清除一个测试游戏，另一个游戏存档应保持；旧版导入前先备份，歧义迁移的原存档不可直接猜测覆盖。
